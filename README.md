# Mini Redis - Java\n\n[![CI](https://github.com/jaimin-valand/mini-redis-java/actions/workflows/ci.yml/badge.svg)](https://github.com/jaimin-valand/mini-redis-java/actions/workflows/ci.yml)\n\n> A Redis-inspired in-memory data server built from first principles in Java 21, with RESP2-style networking, concurrent clients, TTL expiry, lists and append-only persistence.\n\nMini Redis is a systems-engineering project focused on understanding how a networked key-value server works internally. It implements the protocol boundary, command execution, concurrent storage, expiration and recovery path instead of delegating those responsibilities to an existing Redis server or application framework.\n\n## What this project demonstrates\n\n- TCP server and client-session lifecycle\n- RESP2-style request parsing and response encoding\n- command dispatch and typed datastore operations\n- concurrent access using ConcurrentHashMap and per-key synchronization\n- monotonic TTL handling\n- append-only persistence and command replay\n- graceful shutdown\n- deterministic unit tests and dependency-free smoke tests\n- Maven and direct javac build paths\n- GitHub Actions CI\n\n## Architecture\n\n    TCP client\n        |\n        v\n    ServerSocket\n        |\n        v\n    Client worker\n        |\n        v\n    RESP Decoder\n        |\n        v\n    Command Dispatcher\n       /        \\n      v          v\n RedisStore     AOF\n   |   |\n   |   +--> TTL cleaner\n   |\n   +--> strings / lists\n        |\n        v\n    RESP Encoder\n        |\n        v\n    TCP client\n\n## Supported commands\n\n| Command | Purpose |\n|---|---|\n| PING | Connectivity check |\n| ECHO | Return a message |\n| SET | Store a string |\n| GET | Read a string |\n| DEL | Delete keys |\n| EXISTS | Check key existence |\n| INCR / DECR | Atomic integer mutation |\n| EXPIRE | Set a TTL |\n| TTL | Inspect remaining TTL |\n| LPUSH / RPUSH | Add list elements |\n| LPOP / RPOP | Remove list elements |\n| LRANGE | Read a list range |\n| DBSIZE | Count live keys |\n\n## Key engineering decisions\n\n### Protocol isolation\n\nRESP decoding and encoding live in their own package. Command logic does not know about sockets or byte framing.\n\n### Per-key concurrency\n\nRead-modify-write operations synchronise on the affected key instead of putting one global lock around the entire datastore. This keeps the consistency boundary small while allowing unrelated keys to progress independently.\n\n### Monotonic expiration\n\nTTL deadlines use System.nanoTime() rather than wall-clock time. System clock adjustments therefore do not unexpectedly extend or shorten a key's lifetime.\n\n### Command-based persistence\n\nThe append-only file stores RESP-encoded commands. Recovery replays those commands through the same command dispatcher used by live clients. This avoids coupling recovery to internal Java object representation.\n\n### Bounded protocol input\n\nThe RESP decoder limits array length, line length and bulk-string size to prevent unbounded memory allocation from malformed input.\n\n## Quick start\n\n### Requirements\n\n- Java 21 or newer\n- Maven 3.9+ for the full test workflow\n- Bash for the dependency-free smoke test\n- redis-cli is optional and only used as a convenient client\n\n### Build and test\n\n    git clone https://github.com/jaimin-valand/mini-redis-java.git\n    cd mini-redis-java\n    mvn -B test\n\n### Build without Maven\n\n    rm -rf out\n    mkdir out\n    javac --release 21 -d out $(find src/main/java -name '*.java')\n\n### Start the server\n\n    java -cp out com.jaimin.redis.server.RedisServer\n\nDefault port: 6380.\n\n### Connect with redis-cli\n\n    redis-cli -p 6380 PING\n    redis-cli -p 6380 SET name Jaimin\n    redis-cli -p 6380 GET name\n\nExample response:\n\n    PONG\n    OK\n    Jaimin\n\n## Configuration\n\n| Setting | System property | Environment variable | Default |\n|---|---|---|---|\n| Port | redis.port | REDIS_PORT | 6380 |\n| Worker threads | redis.workers | REDIS_WORKERS | 32 |\n| AOF path | redis.aof | REDIS_AOF | data/appendonly.aof |\n| AOF enabled | redis.aof.enabled | REDIS_AOF_ENABLED | true |\n\nExample:\n\n    REDIS_PORT=6380 REDIS_WORKERS=16 REDIS_AOF_ENABLED=true java -cp out com.jaimin.redis.server.RedisServer\n\n## Persistence and recovery\n\nMutating commands are appended to data/appendonly.aof when AOF is enabled.\n\nOn restart:\n\n    AOF -> RESP decoder -> command dispatcher -> datastore\n\nThe replay path deliberately uses normal command semantics so the recovery mechanism stays close to the live execution path.\n\nImportant limitation: the implementation flushes AOF writes but does not fsync every command. A sudden process or machine failure can therefore lose the most recently buffered data.\n\n## Testing\n\nRun the JUnit suite:\n\n    mvn -B test\n\nRun the dependency-free smoke test:\n\n    bash run-smoke-test.sh\n\nThe smoke test compiles production sources directly with javac and exercises PING, SET, INCR, LPUSH and LRANGE without Maven or external runtime dependencies.\n\nGitHub Actions performs both the Maven test suite and a direct javac compilation on every push and pull request.\n\n## Project structure\n\n    mini-redis-java/\n    ├── .github/workflows/ci.yml\n    ├── docs/architecture.md\n    ├── examples/session.txt\n    ├── src/main/java/com/jaimin/redis/\n    │   ├── command/\n    │   ├── protocol/\n    │   ├── server/\n    │   └── store/\n    ├── src/test/java/com/jaimin/redis/\n    ├── pom.xml\n    ├── run-smoke-test.sh\n    ├── LICENSE\n    └── README.md\n\n## Scope\n\nThis is intentionally not a production Redis replacement. The educational implementation currently omits clustering, replication, TLS, ACLs, RESP3, Lua, transactions and advanced eviction policies.\n\nThose omissions keep the core server small enough to read, reason about and extend.\n\n## Roadmap\n\n- [x] RESP2-style request/response framing\n- [x] Concurrent TCP clients\n- [x] String values\n- [x] List values\n- [x] TTL and lazy/background expiry\n- [x] AOF persistence and replay\n- [x] Graceful shutdown\n- [x] Unit tests\n- [x] Dependency-free smoke test\n- [x] GitHub Actions CI\n- [ ] Sorted sets\n- [ ] Pub/Sub\n- [ ] MULTI / EXEC transactions\n- [ ] RDB-style snapshots\n- [ ] Metrics endpoint\n- [ ] Benchmark suite\n\n## Portfolio relevance\n\nThis project is useful as evidence of practical systems engineering because the implementation crosses several layers:\n\n1.
